# Contributing

Start with a small synthetic reproduction, its expected result and a clear explanation of the first divergence. Prefer a correction to a failure class over a new integration or framework.

For the advertised snapshot-reader scope, run `node --test tests/recorded-audit.test.mjs`. Report runtime, OS, failures and skips. The default `npm test` also includes isolated manifest checks. Passing these checks is not a full-engine test result.

The older engine suite has an unresolved execution review. Do not replace its missing evidence with synthetic scores or ask a contributor to work around a host safety block. Any future runtime test must have its own permitted environment, clear scope and bounded execution.

Keep evidence comparisons fair: the same target, input, fault schedule and independent observation must be available to an ordinary Node baseline. Repeated trials of one frozen case are not independent defects. A preferred explanation is not proof of a better detector or paid demand.

Only contribute material you are entitled to share. Include required third-party notices and provenance. Do not submit employer/customer code, personal data, participant responses, credentials or live payment traces. Use deliberately fictitious values and mark them as synthetic. Proposed contributions are reviewed before acceptance; this file creates no contributor agreement or separate rights transfer.
